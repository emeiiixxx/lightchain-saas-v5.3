# 画布整理与适应屏幕：开发交付规则

版本：2026-09-15。适用于 Web 无限画布。本文区分画布坐标与屏幕 CSS 像素；不以物理像素或设备 DPR 计算布局。

## 1. 两个动作的区别

| 动作 | 改变节点坐标 | 改变视图平移／缩放 | 作用范围 |
|---|---|---|---|
| 整理画布 | 是 | 整理结束后自动适应屏幕 | 全部图片及编辑节点，不局限当前选区 |
| 适应屏幕／回到节点 | 否 | 是 | 全部图片及编辑节点的联合边界 |
| 拉伸浏览器窗口 | 否 | 保持倍率，平移以保持中心内容 | 当前视图 |

图片原始比例、尺寸、节点配置、连接关系及选中状态保持不变。整理记录一次历史，可撤销／重做节点位置；视图移动不计入节点历史，撤销不会恢复旧镜头。

## 2. 节点组与固定间距

一张图片及其关联编辑节点构成一个布局组；没有编辑节点的图片独立成组。这里的组只用于整理布局，不是永久编组，不改变独立选择与拖动。

| 参数 | 数值 | 定义 |
|---|---:|---|
| 图片 → 编辑节点 | 80 | 图片右边缘到编辑节点左边缘 |
| 同行相邻组 | 120 | 前组最右边缘到后组最左边缘 |
| 相邻行 | 120 | 上一行最高组的底边到下一行顶边 |
| 组内对齐 | 顶部对齐 | 整理后图片与编辑节点的 y 相同 |
| 行内对齐 | 顶部对齐 | 同一行所有组的 y 相同 |

上述间距均为画布坐标。100% 时对应 80／120 CSS px，50% 时对应 40／60 CSS px。不额外计算阴影、选中描边、Tooltip 或连线。

组宽 = 图片宽 + 80 + 编辑节点宽；组高 = max(图片高, 编辑节点高)。无编辑节点则取图片自身宽高。Demo 编辑节点布局尺寸为 280×579；生产端如果支持动态节点高度，应将实际测量尺寸传入同一几何计算，尺寸变化后下次整理重新计算。

整理使用精确 80／120，不套用拖拽的 32px 网格吸附。用户随后手动拖拽时再按吸附开关处理。

## 3. 整理画布算法

1. 保留当前数据顺序，按添加顺序从左到右、从上到下摆放；不按当前坐标、选中顺序或图片尺寸重新排序。
2. 整理起点为画布坐标 `(0, 0)`。组内编辑节点放在图片右侧 80 的位置。
3. 对 N 个组枚举每行列数 `c = 1…N`。每行放 c 个组，末行允许不足 c 个。
4. 每行从 x=0 开始，按每个组实际宽度加 120 累加；不同宽度的组不会被强行拉宽。下一行 y 为本行 y + 本行最大组高 + 120。
5. 对每种排法计算联合边界 `(Bw, Bh)`，评分 `q = min(Aw / Bw, Ah / Bh)`，其中 Aw／Ah 为第 4 节的可用显示区域。
6. 选 q 最大的排法。比较时不先将 q 截为 100%，避免多个方案都能放下时随意选列数。分数差不超过 `1e-9` 视为相同，保留较少列数。
7. 一次性更新位置并执行第 5 节的适应屏幕。整理同一批内容且窗口尺寸相同，结果必须一致。

宽屏／窄屏不使用固定 5 列等硬编码列数。布局顺序不变，列数随可用区域比例变化。行内距离精确 120；上下行通过整行最高组计算，因此短组下方留白可能大于 120。

批量上传沿用同一排版算法，仅排新上传的组，起点为现有全部节点最右边缘 + 120、y=0；不会移动旧节点。之后适应全部内容，避免新内容被添加到旧编辑节点上。

## 4. Web 可用显示区域

W／H 取画布元素的 `clientWidth`／`clientHeight`，不取整个浏览器窗口高度；48px 顶栏已在画布外扣除，不能重复减去。

可用区域为 `(L, T, W-L-R, H-T-B)`，取值单位为屏幕 CSS px：

| 预留 | W > 1100 | 680 < W ≤ 1100 | W ≤ 680 |
|---|---|---|---|
| L 左侧 | min(96, W×0.20) | 同左 | 同左 |
| R 右侧 | min(32, W×0.10) | 同左 | 同左 |
| T 顶部 | min(176, H×0.35) | 同左 | min(224, H×0.35) |
| B 底部 | min(88, H×0.25) | min(144, H×0.25) | min(144, H×0.25) |

区域宽高至少为 1。此预留对应现有固定项目卡、折叠智能搜索、侧栏、底部工具栏，以及图片选中工具栏上方空间。≤1100px 时底部工具分行，增加底部预留；≤680px 时顶部搜索换行，再增加顶部预留。

临时展开的小地图、下拉菜单、搜索内容、Tooltip 和上传弹窗不改变适应边界，避免打开浮层时画布跳动。窗口极小时预留按比例压缩，仅保证几何计算有效；不能承诺所有固定控件都不遮挡，此时需折叠辅助面板或增大窗口。后续产品固定工具栏尺寸／位置变化时，应同步更新预留规则。

## 5. 适应屏幕算法

包含所有图片和编辑节点，包括视窗外、未选中、独立移动过的编辑节点；不包含连线、阴影、临时浮层和选中工具栏本身。

设联合边界左上角 `(Bx, By)`、宽高 `(Bw, Bh)`，可用区域左上角 `(Ax, Ay)`、宽高 `(Aw, Ah)`：

```text
s = clamp(min(Aw / max(Bw, 1), Ah / max(Bh, 1)), 0.03, 1)
tx = Ax + Aw/2 - (Bx + Bw/2) × s
ty = Ay + Ah/2 - (By + Bh/2) × s
screenX = worldX × s + tx
screenY = worldY × s + ty
```

内容居中于可用区域，不是直接居中于包含固定工具栏的整个浏览器。适应最多 100%，避免将小图片自动放大；用户可用手动缩放继续放大至 400%。计算保留浮点精度，仅百分比文案四舍五入。

最低倍率沿用现有 3%。**当内容跨度在 3% 下仍超过可用区域时，保持 3% 并居中，不保证一次展示全部内容。** 这是 Demo 当前的边界，生产若要求任意规模都完整显示，应统一调整手动缩放和适应的最小倍率，不能只改其中一处。

空画布不显示整理入口；几何函数的空输入返回默认视图 `(tx=0, ty=0, s=1)`。单节点仍沿用同一公式。普通适应动作使用 `200ms ease-out`；减少动态效果时立即完成。

## 6. 浏览器窗口变化

通过 `ResizeObserver` 监听画布实际尺寸，包含浏览器拉伸、侧边面板改变可用宽度等情况。

窗口从 `(W₀,H₀)` 变为 `(W₁,H₁)`：

```text
s₁ = s₀
tx₁ = tx₀ + (W₁-W₀)/2
ty₁ = ty₀ + (H₁-H₀)/2
```

保持画布视窗中心对应的世界坐标和倍率；不自动重排、不修改图片／节点位置，也不持续自动执行适应。即使上次点击过适应屏幕，随后拉伸窗口仍遵循此规则；用户再次点击适应时按新尺寸重新计算。小地图与「回到节点」提示按新视窗同步更新。

## 7. 验收与代码入口

- 图片与编辑节点整理后顶对齐且间距 80；同行组间 120、相邻行间 120。
- 无编辑节点的图片也可参与整理；所有组的原顺序、尺寸、内容和关系保持不变。
- 同样内容在宽屏与窄长窗口下可产生不同列数；相同输入多次整理结果一致。
- 适应屏幕只更新视图，正常尺度下全部内容在可用区域内，且不超过 100%。
- 手动移远的编辑节点参与边界计算；回到节点能定位完整内容区域。
- 记录极端跨度达到 3% 下限的例外，不能将其验收为「已完整展示全部」。
- 拉伸窗口保持中心世界坐标及倍率，重新点击适应使用新区域。
- 整理后撤销／重做恢复节点位置；原有多选、80／120 整理间距与 32px 手动网格吸附互不混用。

实现：`src/canvas.ts`（间距、排版、适应公式）、`src/App.tsx`（整理入口、视窗 ResizeObserver、上传及回到节点）。

自动化几何验收：`node --experimental-strip-types --test tests/canvas-layout.test.ts`（Node 24）。覆盖 1816×1180、1280×752、1024×852、640×1100 画布；1／2／3／7／20 组、空输入、3% 下限、间距、确定性及不修改输入数据。

浏览器验收已通过：实际图片／编辑节点整理后 80px 且顶部对齐；1816×1228 → 1280×800 窗口拉伸保留中心世界坐标与倍率；重新适应后内容进入新安全区域，节点坐标保持不变。
